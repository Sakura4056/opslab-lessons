# 防火墙与端口管理

> 阶段笔记：[[阶段2_网络基础]] ｜ 上一讲：[[阶段2_网络基础/05_网络排错工具箱|网络排错工具箱]] ｜ 下一讲：[[阶段2_网络基础/06_防火墙与端口管理|（本篇为阶段2扩展）]]
> 「端口通不通」的另一半答案在防火墙——排错工具箱的深度扩展。

## 学习目标

- 理解包过滤防火墙的默认策略思想（默认拒绝+按需放行）
- 掌握 ufw 全套操作（Ubuntu 前端）与 iptables 只读排查
- 理解云安全组与主机防火墙的关系（两层都要查）

## 核心概念

```
入站请求 → 云安全组(第一道) → 主机防火墙(iptables/ufw，第二道) → 服务监听
```

**默认策略原则**：`deny incoming, allow outgoing`——只开需要的端口，而不是「先全开再堵」。

## 命令实操

```bash
# ufw（Ubuntu 默认前端，底层仍是 iptables/nftables）
sudo apt install -y ufw
sudo ufw status verbose           # 状态与默认策略
sudo ufw allow 22/tcp             # ⭐ 先放行 SSH！
sudo ufw allow 80,443/tcp
sudo ufw allow from 10.0.0.0/8 to any port 3306   # 仅内网访问数据库
sudo ufw deny 8080/tcp            # 拒绝
sudo ufw enable && sudo ufw status numbered
sudo ufw delete allow 8080/tcp    # 删规则
sudo ufw insert 1 deny from 1.2.3.4   # 插入封禁规则（序号优先）

# iptables 只读排查（看懂即可，别手改）
sudo iptables -L -n -v --line-numbers     # 规则列表+计数器
sudo iptables -L INPUT -n -v | head       # 入站链：看每条规则的 pkts 命中数

# 验证闭环（三步）
ss -tlnp | grep 443                # 服务真的在听？
sudo ufw status | grep 443         # 防火墙真的放行？
nc -zv 127.0.0.1 443               # 本机通；再从外部机器测
```

## 动手实验

- [ ] 启用 ufw（先放 22），验证 SSH 不断线、其他端口被拒
- [ ] 放行 8080，起一个 `python3 -m http.server 8080`，外部 curl 验证；再 delete 规则验证被拒
- [ ] 给 3306 配「仅内网网段」规则，理解来源限制写法
- [ ] 用 `iptables -L INPUT -n -v` 找出 ufw 规则对应的底层链与命中计数

## 常见坑

- **enable 前没放行 22**：云主机自锁（走云控制台/VNC 救援）；
- **只改主机防火墙**：云安全组没放行照样不通——两层逐一确认；
- **ufw 规则顺序**：先匹配先生效，deny 在 allow 之后就被 allow 覆盖；
- **Docker 绕过 ufw**：Docker 发布的端口直接写 iptables，**ufw 管不住**（经典坑，生产注意）。
