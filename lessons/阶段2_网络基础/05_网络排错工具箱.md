# 网络排错工具箱

> 阶段笔记：[[阶段2_网络基础]] ｜ 上一讲：[[阶段2_网络基础/04_HTTP与HTTPS|HTTP与HTTPS]] ｜ 下一阶段：[[阶段3_Shell脚本/01_Shell基础语法|Shell基础语法]]
> 本课是阶段 2 的毕业课：**一套自上而下的排错方法论 + 工具箱**。

## 学习目标

- 掌握「分层定位」排错法：连通→解析→端口→应用
- 会用 nc/tcping/nmap 探测端口与服务
- 能在 10 分钟内独立完成一次标准网络排查并输出结论

## 核心概念：分层排错法（背下来）

```
① 物理连通   ping 网关 → ping 公网 IP
② DNS 解析   dig +short 域名（对比预期）
③ 端口可达   nc -zv host 443 / tcping host 443
④ 服务响应   curl -v http(s)://host
⑤ 应用日志   服务自身 error.log / journalctl
```

**原则：先确认「哪一层开始断」，只测下一层，不跳步。**

## 命令实操

```bash
# ① 连通
ping -c 3 <目标IP>

# ② 解析
dig +short <域名>

# ③ 端口探测三件套
nc -zv <host> 443               # -z 扫描不发送数据 -v 显示过程
tcping <host> 443               # TCP 版 ping（Windows/WSL 已装）
nmap -Pn -p 22,80,443 <host>    # 指定端口扫描（07_Tools 便携版，connect 模式）
nmap -sV <host>                 # 服务版本探测（授权目标才可扫！）

# ④ 应用响应
curl -sSv --max-time 5 https://<host> -o /dev/null

# ⑤ 本机端口与服务
ss -tlnp                        # 本机监听
curl -s http://127.0.0.1:8000/health   # 应用健康检查端点
```

**端口通 = TCP 握手成功**，不代表应用正常——应用层还要看 curl 返回与日志。

## 常见坑

- **对外网/他人主机随意 nmap**：未授权扫描违规甚至违法——**只扫自己的资产**；
- **nc 不加 -z 会挂住**：交互模式看不清是通是断；
- **只 ping 就下结论**：ICMP 通 ≠ 端口通 ≠ 应用正常；
- **云服务器安全组**：本机监听正常但外网不通，先查安全组/防火墙（阶段 4 展开）。
