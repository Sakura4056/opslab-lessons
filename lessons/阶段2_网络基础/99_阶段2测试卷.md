# 阶段 2 测试卷：网络基础

> 时量建议 60 分钟。

## 一、简答（每题 5 分，共 40 分）

1. 192.168.1.0/26 的子网掩码、可用主机数分别是多少？
2. 三次握手中每一步的标志位与 seq/ack 变化？为什么不能两次？
3. TIME_WAIT 存在的意义？大量 TIME_WAIT 的第一优化方向？
4. CLOSE_WAIT 堆积说明什么问题？责任在网络还是应用？
5. DNS 递归解析的完整链路？CNAME 与 A 记录的区别？
6. 502 与 504 的区别？分别指向什么根因？
7. HTTPS 握手后传输用什么加密？证书校验的三要素？
8. 「只 ping 不够」——为什么？端口层面应该用什么验证？

## 二、实操（每题 10 分，共 40 分）

9. 一条命令统计本机 TCP 各连接状态的数量。
10. 抓包验证与 `baidu.com:443` 的 TCP 握手过程（写出 tcpdump 命令并记录 SYN/SYN.ACK 行）。
11. 用 hosts 把 `test.local` 指向 127.0.0.1 并 curl 验证，随后还原。
12. 用 openssl 查 `www.baidu.com` 证书的到期时间。

## 三、场景（每题 10 分，共 20 分）

13. 用户报「网站打不开」：写出你的五步分层排查流程（每步用什么命令）。
14. 服务本机 `curl 127.0.0.1:8000` 正常，外网访问不通——列出至少 3 个可能原因与验证方法。

---

## 参考答案

**1.** 掩码 255.255.255.192；主机位 6 位，可用 2⁶-2=62。（第 01 讲）
**2.** SYN(seq=x) → SYN+ACK(seq=y,ack=x+1) → ACK(ack=y+1)；两次无法让服务端确认客户端能收，且无法防历史连接。（第 02 讲）
**3.** 等待 2MSL 确保最后 ACK 丢失可重传、旧报文消亡；优化方向：应用层长连接/连接池。（第 02 讲）
**4.** 被动关闭方未调用 close()，是**应用代码 bug**；不是网络问题。（第 02 讲）
**5.** hosts → 本地 DNS → 根 → 顶级域 → 权威；A=域名到 IP，CNAME=域名到域名（CDN 用）。（第 03 讲）
**6.** 502=后端返回无效响应（进程挂/异常）；504=后端超时未响应；都看 upstream 与日志定位。（第 04 讲）
**7.** 对称加密；域名匹配/有效期/可信 CA 链。（第 04 讲）
**8.** ping 只证 ICMP 通；端口用 `nc -zv host port` 或 curl 实测应用。（第 05 讲）
**9.** `ss -tan | awk '{print $1}' | sort | uniq -c`
**10.** `sudo tcpdump -i eth0 host baidu.com and port 443 -nn`（观察 [S]/[S.]/[.]）
**11.** `echo "127.0.0.1 test.local" | sudo tee -a /etc/hosts` → `curl -I test.local` → 删除该行。
**12.** `echo | openssl s_client -connect www.baidu.com:443 2>/dev/null | openssl x509 -noout -enddate`
**13.** ①连通 ping 网关/公网 IP → ②解析 dig → ③端口 nc -zv → ④应用 curl -v → ⑤应用日志；先定位断在哪一层。（第 05 讲）
**14.** 服务只听 127.0.0.1（改 0.0.0.0）；防火墙/安全组未放行；监听端口与访问端口不一致；上游 LB 健康检查失败。逐条用 ss/ufw/nc 验证。（第 05 讲+第 06 讲）
