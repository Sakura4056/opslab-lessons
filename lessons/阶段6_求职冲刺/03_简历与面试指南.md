# 简历与面试指南

> 阶段笔记：[[阶段6_求职冲刺]] ｜ 上一讲：[[阶段6_求职冲刺/02_故障排查四套话术|故障排查四套话术]] ｜ 下一讲：（课程终点，冲！）
> 2026 初级运维岗行情基准：**Linux 扎实 + Docker/K8s 会用 + 监控（Prometheus/ELK）+ CI/CD + 脚本**。你的两个项目正好逐条覆盖。

## 学习目标

- 写出「关键词全覆盖 + 项目 STAR 化」的简历
- 准备好两个项目的 5 分钟讲述与追问弹药库
- 建立投递与复盘的迭代流程

## 核心概念：简历结构（一页为准）

```
① 基本信息（姓名/电话/邮箱/城市，一句话意向）
② 技能清单（6~8 条，每条=技能+程度佐证）
   例：熟练 Linux 系统管理（用户/权限/进程/日志），可独立完成生产巡检与故障定位
③ 项目经历（STAR 化，两个项目各 4~6 行）
④ 教育/证书（软考等加分项）
```

**技能关键词对照 2026 JD**：Linux、Shell、Python、Docker、Kubernetes(了解)、Nginx、MySQL、Redis、Prometheus/Grafana、ELK(概念)、CI/CD、Git、Ansible。

### 项目 STAR 化示范（项目①）

```
S 背景：搭建一套可复现的 Web 服务环境用于学习与演示
T 任务：负责 Nginx/MySQL/Redis/Flask 的部署、备份与监控
A 行动：
  - Nginx 反向代理 + systemd 托管 gunicorn 应用
  - 编写备份脚本（mysqldump --single-transaction + 定时清理），并完成恢复演练
  - 建立安全基线（ufw 最小暴露面 / SSH 密钥登录 / 服务自动拉起巡检）
  - 全流程文档化，git tag 版本化管理
R 结果：环境 1 小时内可从零重建；磁盘/服务告警脚本上线，演练 3 类故障全部按预案恢复
```

项目②（容器化）强调：**Dockerfile 分层优化、Compose 编排、镜像固定版本、down -v 卷生命周期理解**。

## 命令实操（其实是「材料准备实操」）

```bash
# 1) 项目②产出物固化（面试可展示）
cd /opt/lnmp && docker compose config > 最终生效配置.yml    # 导出编排
git log --oneline > 变更历史.txt                            # 证明工程化
# 2) 素材整理进 06_Projects\，简历里每个数字/结论都要有出处
```

**投递渠道**：BOSS/拉勾/猎聘 + 牛客内推；**投递节奏**：先投 5 家非目标公司练手感，复盘简历后集中投目标。

## 动手实验

- [ ] 按 STAR 模板完成两个项目的简历段落，对照 10 份真实 JD 逐条勾关键词
- [ ] 准备「追问弹药库」：每个项目预设 5 个追问（为什么选 gunicorn？备份怎么验证？Compose 数据卷？），答案写全
- [ ] 模拟面试 3 轮：让 AI/朋友按 [[阶段6_求职冲刺/01_面试八股速览|八股清单]] + 02 话术提问，录屏复盘
- [ ] 每次面试后 24h 内写复盘：被问倒的题 → 补进八股清单 → 下轮消灭

## 常见坑（求职行为层面）

- **简历写「了解/熟悉」堆满**：写什么都可能被问——只写能扛住追问的；
- **项目只有名词没有数字**：加「1 小时重建」「告警上线后故障平均定位 <15 分钟」这类可验证结果；
- **不问清楚岗位再投**：先看 JD 关键词（有的岗偏桌面运维/机房值守，与你的方向不同）；
- **面完不复盘**：每轮面试都是免费的真题，浪费即损失。

## 自测

1. 你的简历关键词清单里，哪几个能被 JD 全覆盖？哪几个缺口？
2. 项目①的 STAR 四段各是什么？（脱稿说）
3. 「追问弹药库」为什么要提前写？举一个最可能的追问。
