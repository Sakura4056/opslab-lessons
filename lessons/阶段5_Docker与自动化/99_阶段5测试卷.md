# 阶段 5 测试卷：Docker 与自动化

> 时量建议 75 分钟。

## 一、简答（每题 5 分，共 40 分）

1. 镜像分层缓存的利用原则？写出两条 Dockerfile 优化惯例。
2. 容器的数据为什么默认易失？两种挂载方式的区别与场景？
3. `-p 8080:80` 的方向？映射是给谁访问用的？
4. Compose 中服务间如何互访？`depends_on` 的局限？
5. 幂等性是什么？为什么 Ansible/声明式系统看重它？
6. Prometheus/Grafana/Alertmanager 的分工与数据流？
7. Loki 与 Elasticsearch 的取舍？
8. CI 与 CD 的分界？为什么部署前要有审批环节？

## 二、实操（每题 10 分，共 40 分）

9. 写 Dockerfile 构建 Flask 应用（slim 基础镜像、非 root、依赖分层），构建并运行验证。
10. Compose 编排 app+db+cache 三服务并互相联通（写出 yml 与验证命令）。
11. K8s：部署 nginx Deployment ×2 + NodePort Service，完成「杀 Pod 自愈」与「扩缩容」实验（命令+观察记录）。
12. Compose 起监控三件套，Grafana 导入 1860 看板并查询本机内存使用率（PromQL）。

## 三、场景（每题 10 分，共 20 分）

13. 生产 Docker 磁盘 92%，`docker system df` 显示镜像占大头——清理方案与防复发措施？
14. 你的容器应用连不上 Compose 里的 MySQL（报 1045/连接拒绝）——给出排查清单。

## 参考答案要点

**1.** 变动少的层在前（依赖清单先 COPY）、代码后 COPY；slim/alpine 基础镜像、多阶段构建、固定版本 tag、非 root USER。（第 02 讲）
**2.** 容器写层随容器删除消失；volume（Docker 管理寿命）vs bind mount（宿主路径，开发调试）。（第 01 讲）
**3.** 宿主:容器；给宿主外部访问用，服务间互访走网络别名不走映射。（第 01/02 讲）
**4.** 服务名即主机名（自建网络）；depends_on 只保证启动顺序不等就绪——应用侧重试。（第 02 讲）
**5.** 描述期望状态，重复执行结果一致；防止配置漂移与人工差异。（第 04 讲）
**6.** exporter 暴露 /metrics → Prometheus 拉取存时序 → Grafana 可视化 → Alertmanager 分级告警。（第 05 讲）
**7.** Loki 只索引标签成本低、按标签查；ES 全文检索强但资源重——按日志量与检索需求选。（第 07 讲）
**8.** CI 到「构建+测试+产物」；CD 到「部署」；审批防未验证变更直接进生产。（第 05 讲）
**9.** 参考阶段 5 第 02 讲 Dockerfile；验证 `docker run -d -p 8000:8000` + curl。（第 02 讲）
**10.** 参考 docker-compose.yml（environment 传 DB_HOST=db）；验证 `compose exec app ping db`。（第 02 讲）
**11.** `kubectl create deployment/scale/delete pod` + 观察自愈；NodePort 范围 30000~32767。（第 06 讲）
**12.** 1860 看板；PromQL：`100 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m]))*100`、内存按 used/total。（第 05 讲）
**13.** `docker system prune -a`（确认无用镜像）→ 镜像仓库配保留策略 → 定期 prune 挂 cron → 监控 docker system df 告警。（第 01 讲）
**14.** 服务名对不对（不是 localhost）→ MySQL 是否 ready（depends_on 不等就绪）→ 账号密码/主机白名单（app@'%' vs app@'localhost'）→ 网络是否同 compose 网络。逐条 `compose exec app` + `db` 验证。（第 02 讲）
