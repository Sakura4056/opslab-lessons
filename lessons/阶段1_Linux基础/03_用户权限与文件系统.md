# 用户权限与文件系统

> 阶段笔记：[[阶段1_Linux基础]] ｜ 上一讲：[[阶段1_Linux基础/02_vim与文件查看|vim与文件查看]] ｜ 下一讲：[[阶段1_Linux基础/04_软件包与环境变量|软件包与环境变量]]
> 运维核心：**90% 的「Permission denied」都在这一课**。

## 学习目标

- 读懂 `ls -l` 的每一列，尤其是权限位
- 会用 chmod/chown 改权限；理解 sudo 的原理
- 理解 Linux 文件系统：挂载、inode、软硬链接

## 核心概念

### 用户与组

| 概念 | 说明 | 相关文件 |
|---|---|---|
| root | UID=0 的超级用户，无所不能 | — |
| 普通用户 | 每个登录账号，如 ubuntu | /etc/passwd |
| 组 | 用户的分组，便于批量授权 | /etc/group |
| sudo | 以 root 权限执行单条命令 | /etc/sudoers |

### 权限位解读

```
-rw-r--r-- 1 root root 1024 Nov 7 10:00 hosts
│└┬┘└┬┘└┬┘
│ │  │  └── 其他人(others)：r-- 只读
│ │  └───── 所属组(group)：r-- 只读
│ └──────── 所有者(owner)：rw- 读写
└────────── 文件类型：- 文件，d 目录，l 软链接
```

- `r`=4 读、`w`=2 写、`x`=1 执行 → `rw-r--r--` = 644；`rwxr-xr-x` = 755
- **目录的 x** = 能否进入目录；**目录的 r** = 能否列出内容
- `ls -l` 第 3、4 列 = 所有者、所属组

## 命令实操

```bash
# 查看身份
whoami                 # 当前用户
id                     # UID/GID/所有组
sudo cat /etc/shadow   # root 才能读的密码文件（演示 sudo）

# 改权限
chmod 644 app.conf     # 数字法：rw-r--r--
chmod u+x deploy.sh    # 符号法：给所有者加执行权
chmod -R 755 /var/www  # -R 递归目录
chown www-data:www-data /var/www/html -R   # 改所有者:所属组

# 用户管理
sudo useradd -m -s /bin/bash dev1   # 建用户 -m 建家目录
sudo passwd dev1                    # 设密码
sudo usermod -aG sudo dev1          # 加进 sudo 组（-a 追加别覆盖！）
su - dev1                           # 切换用户验证
```

### 文件系统三件事

```bash
df -h                      # 磁盘使用率（挂载点视角）
mount | grep -i snap       # 当前挂载列表
ls -li file1 hard1         # -i 看 inode：硬链接同 inode，软链接不同
ln hard1 hard1.hard        # 硬链接：同一文件的另一个名字，删原文件不受影响
ln -s /var/log loglink     # 软链接：指向路径的快捷方式，原路径失效则失效
```

**inode**：文件的「身份证」，存元数据与数据块指针。硬链接=多名字共 inode；软链接=新文件存路径。**排错意义**：`df` 显示有空间却写入失败 → 可能 inode 用尽（`df -i`）。

## 动手实验

- [ ] 建用户 dev1，sudo 提权，切到 dev1 尝试 `cat /etc/shadow`（应被拒），回 root 成功
- [ ] 写脚本 `hello.sh`，chmod +x 后 `./hello.sh` 运行；再 chmod -x 复现 Permission denied
- [ ] 建 1 个硬链接 + 1 个软链接指向同一文件：删除原文件，分别 cat 观察差异，`ls -li` 对比 inode
- [ ] `df -h` 与 `df -i` 各截一条记录进实验日志

## 常见坑

- **usermod 少了 -a**：`usermod -G sudo dev1` 会把 dev1 踢出其他所有组；
- **chmod 777 图省事**：面试扣分项，生产环境按最小权限来；
- **网站 403**：多半是 nginx worker 用户（www-data）对该目录无 x 权限；
- **sudo 密码输的是自己的密码**，不是 root 的。
