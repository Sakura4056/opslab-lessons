# 软件包与环境变量

> 阶段笔记：[[阶段1_Linux基础]] ｜ 上一讲：[[阶段1_Linux基础/03_用户权限与文件系统|用户权限与文件系统]] ｜ 下一讲：[[阶段1_Linux基础/05_进程与服务systemd|进程与服务systemd]]
> 目标：装得上、找得到、卸得干净。

## 学习目标

- 掌握 apt 的完整工作流（update/install/remove/purge/search）
- 理解 yum/dnf 与 apt 的对应关系（CentOS 系会认即可）
- 理解 PATH 与环境变量，会改、会查、会持久化

## 核心概念

### apt 工作流（Debian/Ubuntu）

```
apt update  → 同步软件源索引（改 sources.list 后必跑）
apt install → 安装包及其依赖
apt upgrade → 升级已装包
apt remove / purge → 卸载（purge 连配置文件一起删）
apt search / show  → 搜索 / 查看包信息
```

软件源配置：`/etc/apt/sources.list` 与 `/etc/apt/sources.list.d/`。

### 与 CentOS 系对照（面试可能问）

| 动作 | Ubuntu (apt) | CentOS (yum/dnf) |
|---|---|---|
| 更新索引/元数据 | apt update | yum makecache |
| 安装 | apt install nginx | yum install nginx |
| 卸载 | apt purge | yum remove |
| 查已装 | apt list --installed | rpm -qa / yum list installed |
| 包格式 | .deb (dpkg) | .rpm (rpm) |

### 环境变量与 PATH

- **PATH**：命令搜索路径。敲 `nginx` 时，系统按 PATH 里的目录依次找同名可执行文件；
- **生效范围**：`export X=1` 只对当前会话；写入 `~/.bashrc`（当前用户）或 `/etc/profile`（全局）持久化；`source ~/.bashrc` 立即生效。

## 命令实操

```bash
# 软件包
sudo apt update && sudo apt install -y tree htop
apt list --installed 2>/dev/null | grep -i nginx
sudo apt purge tree && sudo apt autoremove     # 卸载并清孤儿依赖
dpkg -l | grep ssh                             # 底层包管理直查

# 环境变量
echo $PATH                 # 看当前 PATH（冒号分隔）
which nginx                # 命令在哪个目录（在 PATH 里找）
env | grep -i path         # 看所有相关环境变量
export APP_ENV=prod        # 临时生效（关终端即失效）
echo 'export APP_ENV=prod' >> ~/.bashrc   # 当前用户持久化
source ~/.bashrc           # 立即生效
echo "$HOME 的家目录是 $USER"              # 变量引用：双引号内生效
```

## 动手实验

- [ ] `apt search net-tools` → 安装 → `which ifconfig` 验证 → purge 卸载
- [ ] 把自定义脚本目录加入 PATH：`mkdir ~/bin`，放一个 `hello` 脚本，`export PATH=$HOME/bin:$PATH` 后直接敲 `hello` 运行
- [ ] 对比 `echo '$HOME'` 与 `echo "$HOME"` 的区别（单引号不展开变量）
- [ ] 查看 `/etc/apt/sources.list` 里配置的是哪个镜像源

## 常见坑

- **只 install 不 update**：新装系统或换源后必先 `apt update`；
- **PATH 覆盖写**：`PATH=/my/dir` 会清掉原路径，命令全体失灵——永远追加 `$PATH:`；
- **改了 .bashrc 不生效**：忘记 `source`；或改成了 /etc/profile（那只对登录 shell 生效）；
- **CentOS 用 apt**：两套体系别混，看到 `yum` 知道是 RHEL 系即可。
