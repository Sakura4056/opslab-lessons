# cron 定时任务

> 阶段笔记：[[阶段3_Shell脚本]] ｜ 上一讲：[[阶段3_Shell脚本/02_流程控制与函数|流程控制与函数]] ｜ 下一讲：[[阶段3_Shell脚本/04_综合实战_备份与巡检脚本|备份与巡检实战]]
> 运维自动化的起点：**把脚本挂上时间**。

## 学习目标

- 读懂 crontab 五段表达式，会算任意触发时间
- 会增删查当前用户的定时任务，知道系统级 crontab 的位置
- 掌握 cron 三大经典坑（环境变量/路径/输出黑洞）

## 核心概念

### 五段表达式

```
┌──────── 分钟 (0-59)
│ ┌────── 小时 (0-23)
│ │ ┌──── 日   (1-31)
│ │ │ ┌── 月   (1-12)
│ │ │ │ ┌ 星期 (0-7，0 和 7 都是周日)
* * * * * 命令
```

| 表达式 | 含义 |
|---|---|
| `30 9 * * 1-5` | 工作日 09:30 |
| `0 2 * * *` | 每天 02:00 |
| `*/10 * * * *` | 每 10 分钟 |
| `0 4 1 * *` | 每月 1 号 04:00 |
| `0 9 * * 1,3,5` | 周一三五 09:00 |

**cron 的时间是服务器本地时区**；WSL 要先确认 `date` 正确。

### 两种 crontab

- `crontab -e`：**用户级**（当前用户身份跑，root 的任务要 root 的 crontab）；
- `/etc/cron.d/`、`/etc/crontab`：系统级，多一个「用户」字段。

## 命令实操

```bash
crontab -l                     # 列出当前用户任务
crontab -e                     # 编辑（默认 vi）
sudo crontab -l -u root        # 看 root 的任务

# 例：每天 02:30 备份，日志落盘，错误也记录
crontab -e
# 30 2 * * * /opt/scripts/backup.sh >> /var/log/backup.log 2>&1

# 立即验证脚本而非等 cron：先手动跑一遍
/opt/scripts/backup.sh
```

**最佳实践：cron 只写一行「调用脚本」**，逻辑都在脚本里——便于手动复现与版本管理。

## 动手实验

- [ ] 每分钟任务：`* * * * * date >> ~/cron_test.log`，等 2 分钟观察，然后删除该任务
- [ ] 把阶段 1 的 `sys_check.sh` 挂成每天 09:00，输出重定向到 `~/sys_check.log`，手动触发验证输出内容正确
- [ ] `grep CRON /var/log/syslog` 观察 cron 自己的调度日志（WSL2 + systemd 下可用）
- [ ] 计算练习：写出「每周二和周五 18:30」「每月 1 日和 15 日 03:15」的表达式

## 常见坑（面试也爱问）

- **cron 环境 ≠ 登录环境**：PATH 极短（通常 /usr/bin:/bin）——脚本里要么用绝对路径，要么开头自己 export PATH；
- **输出黑洞**：任务没重定向，报错谁也看不到——养成 `>> log 2>&1` 习惯；
- **路径相对化**：脚本里 `cd app && ./run.sh` 在 cron 里找不到 app——全部用绝对路径；
- **频率过高堆积**：任务执行时间 > 间隔会重叠，加锁文件或拉长间隔。
