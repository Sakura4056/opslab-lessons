## 实战：参数化备份脚本（验收标准）

**验收要求**：不查资料写出 `backup.sh <源目录> <保留天数>`——自动打包、超期删除、失败写日志。

```bash
#!/bin/bash
# backup.sh — 目录打包备份并按天数清理
# 用法: backup.sh <源目录> <保留天数>   依赖: tar, find
set -eu

SRC="$1"; KEEP="${2:-7}"
BACKUP_DIR="/var/backups/custom"

# 参数检查
[ -z "${SRC}" ] && { echo "用法: $0 <源目录> [保留天数]"; exit 1; }
[ -d "${SRC}" ] || { echo "源目录不存在: ${SRC}"; exit 1; }
mkdir -p "${BACKUP_DIR}"

log() { echo "[$(date '+%F %T')] $*"; }

STAMP=$(date +%Y%m%d_%H%M%S)
TARGET="${BACKUP_DIR}/$(basename "${SRC}")_${STAMP}.tar.gz"

log "开始备份 ${SRC}"
tar -czf "${TARGET}" -C "$(dirname "${SRC}")" "$(basename "${SRC}")"
SIZE=$(du -h "${TARGET}" | awk '{print $1}')
log "备份完成: ${TARGET} (${SIZE})"

log "清理 ${KEEP} 天前的备份"
find "${BACKUP_DIR}" -name "$(basename "${SRC}")_*.tar.gz" -mtime "+${KEEP}" -print -delete
log "全部完成"
```

```bash
chmod +x backup.sh && mkdir -p ~/lab/data && echo test > ~/lab/data/a.txt
./backup.sh ~/lab/data 3            # 验证：生成 tar.gz
./backup.sh ~/lab/data 0            # 验证：上一份被清理
# 挂 cron：30 2 * * * /opt/scripts/backup.sh /var/www/html 14 >> /var/log/backup.log 2>&1
```

**逐行自检点**：`set -eu` 保命 → 参数/存在性检查 → log 统一时间戳 → `tar -C` 保持相对路径 → `find -mtime +N -delete` 清理。

## 备份三要素（设计任何备份前先回答）

1. **备份什么**：配置（/etc）、数据（数据库 dump）、代码（/var/www）；
2. **保留策略**：天数控硬盘；重要数据 3-2-1 原则（3 份、2 种介质、1 份异地）；
3. **失败告警**：`set -e` + 输出重定向 + 至少一条通知（邮件/webhook，本期先落日志）。

**恢复演练**：备份的价值=可恢复。每次改备份脚本后，必须实际 `tar -xzf` 恢复一次验证。

## 动手实验

- [ ] 完成脚本并两次执行验证「生成」与「清理」行为
- [ ] 恢复演练：`tar -tzf` 看清单 → 解包到临时目录 → diff 对比原文件
- [ ] 挂 cron（每日 02:30）+ 输出日志，手动 `crontab -l` 确认
- [ ] 复制脚本入 `03_Scripts\shell\backup.sh` 并 git 提交

## 常见坑

- **tar -C 用法**：`-C dir` 后接相对路径，避免压缩包里带绝对路径层级；
- **`${2:-7}`**：参数缺省值写法，缺第二个参数时默认 7 天；
- **备份文件也占磁盘**：不清理 = 磁盘满事故（脚本自带清理就是防这个）；
- **dump 数据库≠备份文件目录**：MySQL 用 mysqldump（阶段 4 展开）。
