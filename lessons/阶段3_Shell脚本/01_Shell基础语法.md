# Shell 基础语法

> 阶段笔记：[[阶段3_Shell脚本]] ｜ 上一讲：[[阶段2_网络基础/05_网络排错工具箱|网络排错工具箱]] ｜ 下一讲：[[阶段3_Shell脚本/02_流程控制与函数|流程控制与函数]]
> Shell 是运维的「自动化双手」：重复三遍的事就该写成脚本。

## 学习目标

- 会写规范的脚本骨架（shebang + 头部注释 + set -e）
- 掌握变量、引号、参数、退出码四大基础
- 理解什么时候用 Shell（粘合命令），什么时候不用（复杂逻辑交给 Python）

## 核心概念

### 脚本骨架（所有脚本以此开头）

```bash
#!/bin/bash
# 备份脚本 — 用途/用法/参数/依赖（三要素注释）
# 用法: ./backup.sh <源目录> <保留天数>
set -e            # 任一命令失败立即退出（推荐起步就加）
set -u            # 使用未定义变量报错
```

### 变量与引号（高频考点）

```bash
NAME="ops"                # 等号两侧不能有空格！
echo "$NAME"              # 双引号：变量展开
echo '$NAME'              # 单引号：原样输出
echo "今天的日期 $(date +%F)"    # $() 命令替换，结果嵌入字符串
FULL="${NAME}-backup"     # 拼接时用花括号定界
```

### 参数与退出码

```bash
# $0 脚本名  $1 $2 第1、2个参数  $# 参数个数  $@ 全部参数  $? 上一条退出码
./deploy.sh prod v1.2     # 执行时传参
echo "环境=$1 版本=$2, 共 $# 个参数"
exit 0                    # 0=成功；非0=失败（cron 和 CI 靠它判断）
ls /not-exist; echo $?    # 试试看退出码是多少（2）
```

## 动手实验

- [ ] 写 `hello.sh` 输出「你好，$USER，今天是 $(date +%F)」并运行
- [ ] 写 `args.sh` 打印参数个数与逐个参数，分别用 0/1/2 个参数执行
- [ ] 故意写 `ls /not-exist` 观察退出码，再加 `set -e` 看脚本提前终止的行为
- [ ] 把 `hello.sh` 移入 `~/bin`（阶段 1 配好的 PATH）直接运行

## 常见坑

- **等号两边有空格**：`NAME = "ops"` 会被当成命令执行；
- **变量没加引号**：路径含空格时 `cd $DIR` 断裂——写 `cd "$DIR"`；
- **忘了 shebang**：用 sh 执行时行为可能与 bash 不同（数组等不支持）；
- **CRLF 换行**：Windows 编辑过的脚本报 `bad interpreter`，`sed -i 's/\r//'` 修复；
- **把复杂逻辑硬写 Shell**：超过 ~200 行/要数据结构 → 换 Python（阶段 5）。
